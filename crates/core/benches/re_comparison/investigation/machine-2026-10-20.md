# New-machine comparison, 2026-10-20

The user reports an 18-core MacBook host. This workspace runs inside an Apple
ARM Linux VM exposing **10 virtual CPUs** (`/sys/devices/system/cpu/online` is
`0-9`). Its container CPU quota is unlimited (`cpu.max = max 100000`), but the
guest cannot schedule on host cores that the VM does not expose. The previous
benchmark environment also exposed ten CPUs. These measurements compare the
available environments at the same worker count; they are not native macOS or
18-core host measurements. The host chip model is not exposed to this guest.

## Comparable maximization kernels

Release Rust 1.89.0, pinned mimalloc 0.1.52 v2 / libmimalloc-sys 0.1.49, option
26 = 0. Use the existing uninstrumented comparison executable and unchanged
frozen inputs. No concurrent builds, tests, or other benchmark jobs. Three
samples, alternating serial/parallel order; matching repeats 30 kernels per
process. Compare complete maxima across worker counts, not only their row counts.

Previous timings reuse the final integrated records from 2026-10-13. They are
RE3 timings on the previous environment, not timings of the original RE1 code.

| Kernel | Workers | Previous elapsed | Current elapsed | Speedup | Previous CPU | Current CPU |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Matching, fixed step-ten maximum | 10 | 14.826 ms | 9.627 ms | 1.540× | 49.835 ms | 32.950 ms |
| Large fixture, fixed second maximum | 10 | 1.123 s | 0.719 s | 1.561× | 2.928 s | 1.906 s |
| Large fixture, fixed second maximum | 1 | 2.358 s | 1.467 s | 1.607× | 2.360 s | 1.467 s |

Ten-worker elapsed time decreases by approximately 35–36%. The single-worker
large case decreases by 38%, supporting a gain independent of adding workers.
CPU is aggregate process user+system time, including all workers and process
preparation; kernel elapsed excludes parsing and result dumping. This does not
isolate hardware from changes in the VM/operating-system environment, establish
performance on all problems, or predict scaling from ten to eighteen CPUs.

Measure actual `round_elimination::apply` calls with source maximization and
set-label conversion, fresh uncached snapshots, and ten workers. Medians of

## Reproduce

```sh
python3 crates/core/benches/re_comparison/run.py --allocator mimalloc-v2 \
  --build-only --target-dir /tmp/re3-new-machine-target
python3 crates/core/benches/re_comparison/compare_work.py \
  --binary /tmp/re3-new-machine-target/release/re-comparison-mimalloc-v2 \
  --workers 1 10 --samples 3 --output /tmp/new-machine-work.jsonl
python3 crates/core/benches/re_comparison/run.py \
  --binary /tmp/re3-new-machine-target/release/re-comparison-mimalloc-v2 \
  --threads 10 --steps 10 --samples 3 --modes new-re \
  --output /tmp/new-machine-re.jsonl
```

No algorithm or allocator settings were changed for these measurements. To
measure all eighteen host cores, increase the VM's CPU allocation or run the
benchmark directly on macOS. A different number of Rayon workers alone does not
make additional physical CPUs available to this guest.
